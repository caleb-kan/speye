## Reproduced defects and corrections

### Mobile navigation and feature access

The top navigation could overlap header controls at phone widths. Mobile
navigation now has a labeled bottom bar with reachable targets and safe-area
padding. Home selects RSVP on mobile, including when desktop preferences
contain another reading mode. Desktop reading modes remain available.

Mobile now exposes the theme picker, library summaries, upload and sorting
labels, keyboard shortcut reference, legal links, PvP user search, rating
history, match history, and all leaderboard columns. The leaderboard retains
horizontal scrolling inside a labeled, keyboard-focusable region.

The shared mobile layout now uses natural vertical flow. This prevents
short-screen reading content, controls, and the footer from collapsing over
one another. Reading options wrap, scroll, and unmount when collapsed so
hidden inputs cannot keep reading blocked or receive keyboard focus. The
install banner and PvP progress bar sit above navigation. Offline status and
notification overlays fit the viewport and retain accessible dismissal.

Long email addresses, notification links, titles, and admin usernames wrap.
Admin panels stack below desktop widths, quiz answer inputs can shrink, and
preview and confirmation dialogs keep their actions accessible. Modal drafts
reset when changing texts or reopening and survive refreshes of the same
text without a state-reset effect or lint suppression.

### Offline authentication and PvP recovery

Queued work previously remained unsent after online reauthentication unless
the user selected Sync Now. Authentication and token refresh now trigger the
existing guarded sync, including authentication changes during an older sync.

Navigating away from an active PvP game and returning previously restarted
reading at word one and discarded timing. A validated game-and-user-scoped
session now preserves position, original timing, and completed-reading WPM.
Completed reading resumes into the quiz without another activity record.
Document reload retains the existing forfeit contract.

Pending result recovery waits until text and quiz validation finish. Confirmed
server results restore waiting or terminal screens without another submit.
Submission guards survive StrictMode effect replay. Pending backups carry
account ownership; legacy backups without ownership cannot be attributed
safely and are discarded. Terminal game state and confirmed participant completion remain authoritative
when delayed events arrive through another update path. Equal-status stale
rows cannot remove confirmed waiting-screen performance metrics.

### Text processing, moderation, and expired leaderboards

Authenticated owners could forge server processing or moderation fields.
The hosted Supabase change adds a guard for those fields while preserving legitimate
private manual quizzes and trusted workers and admin RPCs. Source edits
invalidate generated quiz, summary, and moderation state and enqueue one
fresh processing job. No-op source updates do not enqueue duplicates.

Rejected policy-violation text cannot bypass moderation through retry.
Transient retries and explicit admin overrides retain their intended paths.
Admin edit authorization uses signed app metadata. Live function ownership,
grants, triggers, policies, and worker revision checks informed the fixtures.

Matchmaking locks the chosen passage until its game commits. Owner editing
cannot change a passage used by a pending or active game. Tests cover both
transaction orderings. Admin approval locks and rereads the current revision;
it cannot approve a newly edited, unprocessed source after waiting for its
owner transaction. Both completed-text and prior policy-rejection races are
covered.

Expired or malformed Redis hashes previously produced misleading zero-score
leaderboard entries. Invalid statistics now use the established database
fallback. Valid zero scores remain supported.

## Coverage limits

“Could not find profile folder.” The Linux Playwright container exercises
Firefox; its result is required at the merge gate. Chromium and WebKit run
locally as well. Native browser MCP navigation did not yield a usable rendered
page, so runtime evidence uses the repository's Playwright installation.

Browser emulation does not verify physical iOS or Android devices, hardware
keyboards, camera calibration, real OAuth consent, or assistive hardware.
Mocked two-player scenarios do not establish real multi-account WebSocket
load behavior. The isolated SQL checks initially used simplified fixtures. Those fixtures
and all SQL migrations were removed from the repository at the user's request.
Sanitized verification evidence is preserved outside the checkout. Hosted
rollback and metadata checks exercise actual Supabase behavior.
Paid inference and exhaustive concurrency or load testing are outside this
verification. Existing paid-plan security settings are reported without
changing the subscription.

## Mobile Library pagination follow-up

The initial mobile fixture contained three texts and never rendered
pagination. A three-page fixture reproduced the reported overlap at 320px:
pagination ended at y=828 while the bottom navigation started at y=780.
Mobile pagination now stays in normal Library page flow, so it cannot cover
the global navigation or footer. All four arrows and page jumping remain
available, with 44px controls and bounded input width. Native scroll margins
preserve keyboard access around the fixed header and navigation. Desktop
pagination keeps its existing fixed positioning and scroll-dependent style.

Deleting the only item on the last page also exposed stale page arithmetic:
the displayed page clamped to the new total while Previous decremented the
old stored page and appeared to do nothing. Previous now steps back from the
visible page. A hook regression reproduced this defect, and all five browser
viewport scenarios now delete the final page item and verify one-click
backward navigation. The aggregate frontend suite passes 2,006 tests.

Ten focused Chromium and WebKit cases passed at five portrait, landscape,
short, and desktop sizes. They exercise three pages, long numeric input,
simulated safe-area spacing, and footer and navigation hit tests. Independent
runtime review additionally verified native focus after scrolling to the
footer at 320x240 with a simulated 30px safe-area inset. Physical devices and
their virtual keyboards were not tested.

Four existing form tests left delayed upload, edit, and public-copy callbacks
pending at teardown. An intermediate main CI run reported a window access
after teardown despite its assertions passing. Those tests now wait for
completion and the busy state to clear; all 42 form tests and the aggregate
2,005 frontend tests passed. Final Linux CI and deployed release evidence
remain separate release gates.
